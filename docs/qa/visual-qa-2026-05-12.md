# Visual QA — ailevel.app — 2026-05-12

## Health score: 68/100

**Deployment is reachable, performant, and renders cleanly on desktop + mobile.** No JS console errors on any public page. Layout is solid, no overflow. Hero, curriculum, evidence, FAQ, and footer all render as intended.

Score is held below 80 by three real issues: **all three footer legal links are dead (404)**, the **brand palette and typography on the deployed build don't match the task brief** ("Kapitus deep-indigo + oxblood + Fraunces titles"), and the **404 page itself is un-rebranded** — it still shows the old generic LevelUp navigation (Governance/Pricing/FAQ/Request demo) instead of the Kapitus header. There's also a small redirect-loss bug on `/coach` and `/assessment`.

Methodology: gstack `browse` (Playwright) against the live site, viewports 1280x800 and 390x844. No accounts created, no authenticated routes entered.

## Critical (blocks ship)

### C1. All three footer Legal links return HTTP 404

- **Pages:** every page (footer is global). Direct URLs:
  - https://ailevel.app/legal/privacy → 404
  - https://ailevel.app/legal/terms → 404
  - https://ailevel.app/legal/security → 404
- **Viewport:** both desktop + mobile (footer rendered identically).
- **Repro:** load `https://ailevel.app`, scroll to footer, click `Privacy` (or `Terms`, or `Security`). HTTP 404 + the generic 404 page shown.
- **Why critical:** GLBA + SOC-2 messaging is the central pitch of the landing page ("GLBA-aligned · SOC 2 in progress", "Quarterly governance reports your CISO can hand to auditors"). Shipping a marketing site that _claims compliance posture_ while its own Privacy / Terms / Security pages 404 is a credibility break and an actual legal liability for a regulated-FI customer (Kapitus).
- **Screenshot:** `screenshots/legal-privacy-404.png`, `screenshots/footer-desktop.png`

## High

### H1. 404 page is un-rebranded — leaks old LevelUp/“ailevel” identity and dead nav

- **Page:** any 404 (e.g. `/legal/privacy`, `/catalog`, `/map`).
- **Viewport:** desktop 1280x800.
- **What's wrong:** the 404 page renders a **completely different header** — wordmark is `ailevel / ACADEMY` (not `Kapitus AI Academy`), nav links are `Governance · Pricing · How it works · FAQ` (none of which exist as standalone pages on the current site), and the CTA is `Request demo →` (a demo-funnel CTA inappropriate for the internal Kapitus deployment).
- **Repro:** navigate to any URL that 404s, e.g. `https://ailevel.app/legal/privacy`.
- **Why high:** every customer who clicks a footer Legal link lands here. So C1 and H1 are a double-failure on the same path. Also a strong "leftover from a different product" smell on a tenant-branded deployment.
- **Screenshot:** `screenshots/legal-privacy-404.png`

### H2. Deployed brand does NOT match the spec from `apps/web/tailwind.config.ts`

- **Pages:** every public page.
- **Spec (per task brief):** Kapitus brand should be deep-indigo + oxblood with Fraunces serif titles.
- **What's actually deployed:**
  - Primary button colour is `rgb(145, 0, 224)` — a saturated violet/magenta. Not deep-indigo, not oxblood.
  - Section eyebrows (`KAPITUS AI ACADEMY`, `HOW IT WORKS`, `KAPITUS AI ACADEMY` on sign-in/sign-up) are the same bright magenta.
  - `getComputedStyle(document.documentElement)` exposes no `--brand-indigo` or `--brand-oxblood` custom properties. The brand tokens that _do_ exist on `:root` are `--ink-*`, `--paper-*`, `--signal` (orange `255 179 0`), `--success`, `--warning` — i.e. the _generic_ LevelUp design tokens, not the Kapitus override.
  - Both `body` and `h1` resolve to `font-family: Manrope, "Manrope Fallback", system-ui, sans-serif`. Fraunces never loaded — it's not among the five preloaded woff2 files.
- **Verification:** `$B js "getComputedStyle(document.querySelector('a[href=/sign-up]')).backgroundColor"` returns `rgb(145, 0, 224)`. `$B js "getComputedStyle(document.querySelector('h1')).fontFamily"` returns the Manrope stack.
- **Why high:** the rebrand the task explicitly references is not on prod. Either the Tailwind theme override isn't being applied, or the deployed build is from before the rebrand commit, or there's a `KAPITUS_BRAND` env flag not set in Vercel.
- **Screenshot:** `screenshots/landing-desktop-hero.png`, `screenshots/sign-in-desktop.png`

### H3. `/coach` and `/assessment` lose the deep-link target on sign-in redirect

- **Pages:** `https://ailevel.app/coach`, `https://ailevel.app/assessment`.
- **Repro:**
  1. Visit `https://ailevel.app/coach` while logged out → server redirects to `https://ailevel.app/sign-in?redirect=%2Flearn` (not `?redirect=%2Fcoach`).
  2. Visit `https://ailevel.app/assessment` while logged out → same: `?redirect=%2Flearn` (not `?redirect=%2Fassessment`).
  3. Compare with `/admin` → correctly redirects with `?redirect=%2Fadmin`, and `/learn` → correctly redirects with `?redirect=%2Flearn`.
- **Why high:** any email / external link that points a user at `/coach?...` or `/assessment/:id` will dump them at `/learn` after sign-in, losing intent. Likely a hard-coded fallback in the middleware for the (learn) route group.

## Medium

### M1. `/pricing` silently redirects to `/#pricing` — and there is no `#pricing` section on the page

- **Page:** https://ailevel.app/pricing
- **Repro:** navigate to `/pricing`. Browser URL bar shows `https://ailevel.app/#pricing` after redirect. Page is the landing page. There is no `id="pricing"` block; the closest is the **"What you get"** section, which is what gets scrolled to. The landing nav uses `What you get → /#pricing` — so the anchor "works" only because it points at a section explicitly given `id="pricing"` for marketing purposes, but the link label and the section heading don't match the URL slug.
- **Why medium:** the redirect avoids a 404 but the URL is misleading (no real pricing on a Kapitus internal site — it's bundled), and the 404 page itself still advertises `Pricing` as a nav item. Decide: either ship a real pricing page or stop linking to `/pricing`.

### M2. Bright magenta on dark hero — contrast is fine, but the "0" counter in the dashboard mock is hard to read at a glance

- **Page:** `/` hero, right-hand dashboard card.
- **Viewport:** 1280x800.
- **What's wrong:** the big "0" for "Sensitive data triggers" is rendered in the same `rgb(145, 0, 224)` magenta on a white card on a dark hero. Visually it pops as the brightest element on the page above-the-fold, but the numeral itself reads as small relative to the surrounding metadata. Minor — and tied to H2 if the brand palette swap happens, so probably auto-fixed.
- **Screenshot:** `screenshots/landing-desktop-hero.png`

### M3. `/catalog` and `/map` 404 — both reachable from the curriculum-CTA copy intent

- **Pages:** `/catalog`, `/map`.
- **What's wrong:** the landing copy says "Browse The Catalog" (linked to `/#how-it-works`, OK) but `/catalog` itself 404s, and recent commit `1b075e1 feat(academy): step-by-step curriculum — tiers, prereqs, map page, next-step CTA` references a "map page" — `/map` 404s as well. Likely those pages are auth-gated under a different path (`/learn/catalog`, `/learn/map`) and the bare `/catalog` / `/map` aren't intentional public routes — but they're not handled cleanly either. The 404 they hit is the un-rebranded one (see H1).
